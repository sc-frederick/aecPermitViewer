# Interface notes

The first user is a permit professional reviewing several saved public records. The surface is an Operate tool in the warm Aether system shared with AEC Plan Search: one page with an add-permit card and a "Permits" card with a table. Detail and settings open in a right-side sheet so the list stays in view.

## Truthfulness rules

- Portal status text is shown exactly as the portal displayed it, in neutral styling. It never gets a color or icon itself.
- The Action column is the one interpretation, and it sits beside the status rather than on it: AEC (the applicant owes the next step), AHJ (the authority has it), or None (issued, finished, or withdrawn), looked up per authority from the wording in [the status survey](PERMIT_STATUSES.md). When in doubt it says AEC?: the survey's "AEC, to be safe" wording (records that stopped short, or wording it couldn't pin down) and wording not on the authority's list. The badge's tooltip gives the reason. Water management district permits and permits without a verified status show a dash, never None.
- Otherwise color marks the app's own check results in the "Last check" column and the history timeline: an ink dot for verified, oxide red (`#a8331a`) for a failed attempt, and a pulsing ember dot for a queued or running check. Cancelled and never-checked use neutral text.
- When the latest check failed, the row keeps the older verified status and its original time; the failure shows only in the Last check column.
- The filter tabs use facts the app recorded ("Failed", "No status yet") and the Action column ("AEC action" lists AEC and AEC?). A filter with nothing to show says "No matches.", never an all-clear.
- Record links are available only after a verified observation.

## Structure

- Header: the app icon and "Permit *Monitor*" wordmark (the page heading), when the next scheduled check runs, and Settings. The layout stays minimal: copy is kept to labels and short messages. No headlines, stat readouts, section titles, subtitles, helper paragraphs, decorative imagery, or footer.
- A hairline-framed banner with an ember left rule appears whenever the key is missing or key storage is unavailable.
- Add a permit: one card with an explicit issuing-jurisdiction select, the full permit number, "Add permit", and the Show filter (All permits, AEC action, Failed, No status yet, with counts). The select groups "Counties and cities" and "Water management districts". The jurisdiction's coverage and access note appears before saving, and the number field's placeholder shows that authority's number format when it has one. Validation errors appear inline under the form.
- Permits: a table with Permit, Status, Action, Verified, Last check, and row actions (Check now or Cancel, plus open the verified record). The permit number opens the details sheet. The Action cell is an Aether badge: AEC has a 1px ember frame, an ember dot, and semibold ink text (ink rather than ember text keeps small type above AA contrast), with a consistent warm fill; AEC? has the same dot with a dashed frame and medium-weight text; AHJ has a fog frame and a prism-cyan dot; None is plain graphite mono text. A "Not scheduled" tag marks permits excluded from scheduled checks. The empty state is one short line.
- Projects: after a permit is added, a small dialog asks for the user's own project number (Skip or Add), prefilled with the last one used and offering recent ones as chips. Once any permit has a project number, the table groups permits under soft warm band headers ("Project 28069 · 3 permits") in natural order, with "No project" last; each group is its own `tbody`.
- Details sheet: current status, verification time, and its Action badge, Check now, Open record, the project number (saved on Enter or leaving the field; blank clears it), the scheduled-check toggle with that permit's next check time, the full check history, and Remove permit.
- Settings sheet: TypeSafe key (a password field that sends the key once for encryption, clears itself, and never shows the key again; replace or remove), background and notification switches, signed full-installer updates, shared list, and local-data deletion.
- Shared list: while off, one line of copy, a Share this list button, and a code field with Follow. While sharing, the code sits in a read-only mono field with Copy, and Stop sharing is a ghost link. While following, Stop following. Whenever sharing or following, a Sync now ghost button (Lucide refresh icon) sits in the header before Settings: it sends the list now, or fetches the newest copy now. A status line says when the list was last sent or received, or why the latest attempt failed. Following swaps the window to the followed list, read-only: the add fields, Check now and Cancel, the scheduled-check toggle, and Remove permit are hidden, the project number field is read-only, the key banner stays down, and the header says "Shared list · updated …" (or "couldn't update") where the next check time would be. The Show filter, details, history, Action badges, and record links work as usual. Following another list over a non-empty list of one's own asks first; stopping sharing and stopping following ask too.
- Destructive or disruptive actions (remove permit, delete local data, install update) use an in-app confirm dialog.

## Background and notifications

- Closing the window hides it; Permit Monitor keeps running from the notification area. The first time this happens, one notification explains where the app went. The tray menu offers Open, Check all permits now, a Scheduled checks toggle, and Quit. The tray icon gains an ember dot while any permit's latest check has failed.
- Desktop notifications fire only for facts the app recorded: the first status for a new permit, a change in the portal's exact wording (old and new quoted, followed by "Action: AEC" or "Action: AEC?" when the new wording waits on the applicant), and the first failure in a row. Repeat failures and unchanged statuses stay quiet. A missing or unreadable key skips checks without recording failures, with one notice (and one for each Check now); a rejected key pauses scheduled checks until a new key is saved. When the window is in front, the same message shows as an in-app notice instead.
- Clicking a notification opens that permit's details sheet.
- Settings has four switches: keep running when closed, start at Windows sign-in (installed app only, off by default), status-change notifications, and failure notifications.

## Visual system

The renderer uses the same complete Aether design system and final polish as AEC Plan Search 0.3.3, selected by the user. The original system lives in `assets/aether/aether.css`; product styling and warm overrides live in `src/renderer/styles.css`. It is light-only.

- Warm pearl `#f6f1eb` with peach `#f4c8a2`, amber `#f9dfb6`, and a pale orange lower glow. White-alpha glass surfaces, graphite `#1d1d1f`, slate `#54545a`, contained shadows, soft bevels and hairlines. Embers and oxide still identify the app's recorded action/check states; portal wording stays neutral and exact. Blue remains the keyboard focus color.
- Locally bundled Inter for headings, controls and text; JetBrains Mono for permit identifiers and timestamps; project names use Inter. Body 13–14px, metadata 11–12px, wordmark 16px, sheet headings 22px. No serif, uppercase button lettering, or wide tracking.
- Floating command dock; add form and permit table use 20px rounded panels. The table uses restrained rows rather than separate cards for each record. Permit, authority, exact status, action, verification, last check, and actions remain visible. Project grouping, review prompts and schedule exclusions remain intact; full review evidence and history live in the details sheet.
- Buttons are 36px, dense table buttons 30px, form inputs 40px; primary Add uses a 28px icon chip. Lucide icons inherit currentColor at 1.75px. Close buttons remain centered when hovered, with no offset inset bevel.
- The permit table scrolls inside a padded rounded panel, with a sticky column header and balanced column widths. The dock, form and table share the same fluid gutters and expand with the window, without a desktop width cap. Timestamp columns stay readable; followed lists use a compact horizontal filter and reserve only the record-button width. Project bands have quiet spacing, rows share an opaque warm surface, and action badges carry the applicant emphasis without broken edge rules. At the 820px minimum window width, horizontal scrolling keeps every action reachable rather than squeezing columns. The header, add form and filter remain in view. Both scrollbars use the same inset 8px track with no arrow buttons.
- Native customizable selects retain grouped options, keyboard behavior and accessibility. Their top-layer picker has 16px rounded corners, bounded height, inset options, charcoal selection, and an 8px gap below the control. No parent clips the picker.
- Details and Settings are rounded 24px side sheets with independent scrolling. Manual checks, project prompts, confirmations, notices, schedule rows, sharing controls, banners, errors, and disabled states follow the same system.
- The still amber background uses locally bundled Shaders 4.0.4: MultiPointGradient plus non-animated FilmGrain. It probes WebGPU before loading the engine, caps resolution at one pixel per CSS pixel, and paints only at startup or resize. There is no telemetry or idle animation. The CSS gradient remains underneath on no-GPU devices or initialization failure. Reduced motion, reduced transparency, and forced colors disable the shader; preferences update while the window is open. CSP remains unchanged.
- The FileCheck mark sits in a charcoal circle in the dock, application icon, tray and installer. The tray attention dot still marks failed checks. Bundled licenses are in `assets/aether` and `assets/fonts`.

Portal content and the API key never render in the app window. Keep each jurisdiction's coverage and access limits visible before a permit is saved.
